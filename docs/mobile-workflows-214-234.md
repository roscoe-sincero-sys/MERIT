# Phone workflow and visualization improvements

Issues #214, #220, #221, #229, #230, #231, #232 and #234 were checked against merged main before implementation.

| Issue | Verified current behavior | Implementation / alternative |
| --- | --- | --- |
| #214 | Patient trend geometry and labels scaled together; figure margins consumed phone space. | Resize the existing server SVG geometry to its available CSS width while keeping margins, text and point targets in screen pixels. Remove figure side margins, preserve the desktop width cap, units, sample descriptions, original links and current-reference-date caveats. A direct link reaches the labeled result records. |
| #220 | Every case filter preceded results on phones. Recent merged work already provided debounced search and filtered return links. | Keep search and result count near the top, and put secondary filters in a native disclosure on phones. Its summary counts active secondary filters. Apply/Clear, keyboard operation, filter URLs and returning from a case remain supported; desktop keeps the controls open. |
| #221 | Patient result, place and relationship tables still required horizontal panning for status and actions. | Reflow the same tables into labeled records on phones, retaining table/header/row/cell semantics and keeping record actions with their source row. Desktop tables remain tables. No duplicate forms or identifiers are introduced. |
| #229 | Reports still scaled a fixed SVG. The map already drew at its actual width, but had small text and targets. | Reports draw at measured width, keep readable screen-sized text, reduce category ticks, and use the wrapping legend rather than tiny end labels on phones. Map ticks/names are larger and less crowded; markers retain classification shapes with 24px hit areas. Pointer selection offers a case chooser for nearby markers. Existing tables/lists have direct links. |
| #230 | Authenticator input used a text keypad. Audit already contained record type/ID, but phones could not comfortably read the wide 100-row view. Fit and held-group buttons were small text actions. | Numeric keypad for authenticator codes; recovery mode stays text. Phone audit entry requests 25 events and displays labeled event records. `Next 25 events` uses bounded page navigation instead of unbounded append, preserving scope, filters, reload and browser history. Desktop defaults to 100, with explicit 25/100 selection. CSV limits are unchanged. Small held/map actions have usable touch areas and consistent styling. |
| #231 | Held rows had no card mode, and the inspector lacked a row-specific matching action. The actual hold code is `uncertainMatch`, not the older example in the issue. | Enable existing grid cards, expose the exact Match review link before inspector fields, explain the disabled release action, and stack inspector fields on phones. Fix CDK-created row-group sizing so real held data cannot stretch cards beyond the viewport. |
| #232 | End place was already behind a disclosure; it still assumed today's date and lacked confirmation. Listboxes did not account for the visual viewport. | Require an explicit end date in UI and controller; show that date and the consequence in the shared confirmation. No request is sent on cancellation. Position listboxes within the visible viewport, flip when necessary, and bring an obscured picker into view when the keyboard changes viewport geometry. Ordinary page scrolling does not forcibly recenter the field. |
| #234 | Map roving focus already existed. Timeline placed every SVG mark in sequential Tab order and scaled targets down with its viewBox. | Retain the map's spatial order, Home/End, pan/zoom and exact keyboard selection. Add chronological roving focus to the timeline and screen-sized 24px hit areas to both visualizations. Timeline Enter/Space selects; Tab leaves the plot. Dense events remain available in the labeled lifetime list. Patient chart links also use roving focus. |

The issue's blanket statement that individual SVG tab stops necessarily violate WCAG 2.1.1 is not used as a compliance claim. Roving focus improves efficiency while preserving keyboard access. Similarly, the 12px text target is a readability design goal, not a claimed WCAG minimum font-size rule. Target geometry is measured in rendered CSS pixels, not just SVG units.

## Validation and limits

- Unit and integration checks cover valid/encoded SVG, preserved point descriptions, explicit missing-date rejection without changing a place record, bounded audit page sizes and unchanged filtering/export behavior.
- Edge checks measure rendered text and targets at phone widths, exercise dense chronological navigation and spatial map navigation, select nearby cases, verify phone records and filter return paths, cancel/accept place ending, navigate from a held inspector to its exact match, and verify numeric/recovery keypad modes.
- Visual-viewport tests simulate the keyboard-reduced visible area and verify suggestions remain selectable. Existing desktop forms, lookup, keyboard and accessibility regressions are also checked.
- Database tests use `MERIT_IT`; no production deployment or schema change is required. Physical iOS/Android keyboards and full assistive-technology testing remain manual validation limits.

Recorded validation on 8 November 2026: 308 unit tests passed (five optional local mail-tool skips), 168 integration tests passed, and 61 distinct affected Edge scenarios passed across the initial selection and focused reruns. Angular production build, browser TypeScript checks, JavaScript syntax checks and the final web build passed. Phone screenshots were also inspected for readable chart labels and complete held-card context. Existing test fixtures were updated for merged filtered-return URLs, empty-section disclosures and independent MFA enrollment; the safety assertions were retained.
