## PR #122 review follow-up

All nine finding groups were verified and addressed:

1. **Real authorization denial:** use the explicit marker and disable status-code-page re-execution instead of inferring denial from the body. Real GET and POST denial tests verify this path.
2. **Pending timers:** clear both timers on confirmed expiry and ignore repeat expiry notifications. A browser clock test crosses the old deadlines while the draft retains focus and the original alert stays in place.
3. **Sliding-expiration wording:** the incoming ticket remains a conservative deadline. Timer messages invite checking a session that *may* have expired and do not steal focus. Only a server 401 confirms that the session ended. A clock-driven test verifies the tentative message while the actual server still accepts the session.
4. **Report measures:** measure-only URL changes and Back/Forward reuse the loaded report. Code/date/analyte changes and an explicit Apply refresh request fetch data. A request-count test checks both paths.
5. **Cancelled overview reads:** failed queue/held writes restart the side-nav/overview read, preserving the original write error, selection and corrections. Tests hold the first read pending, fail the write, and verify the recovered counts.
6. **Corrected page URLs:** `ViewQuery.replaceLoaded` acknowledges the already-loaded query without invoking its reader again. A test verifies one GET for an out-of-range page and normal later filter/Back reads.
7. **Audit recovery:** the task and held services settle paging before recording a list view. Integration tests check a single event for recovered task and batch-filtered held pages, including an empty task dataset.
8. **Shared state and paging:** the grid, match review and clusters use one pager. Each review list supplies its page-size state to both the API and pager and updates that state from the response. Reports read the code solely through the query callback, including after library loading.
9. **Minor cleanup:** API 401 notifications come only from the HTTP interceptor; `problemMessage` is a formatter. A browser test checks one event per 401. The unused out-of-order web infrastructure import was removed when paging moved to the application layer.
